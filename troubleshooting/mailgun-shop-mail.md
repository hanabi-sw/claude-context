# Mailgun (Sinch) — NEH shop mail logs — READ-ONLY

Mailgun is the outbound mail relay of the **NEH platform only** (Nordisk eHandel shop hosts,
`neh` / `neh-infrastructure`). SWS does not use it; for SWS order e-mails see
`worker-queue-cron.md`.

Use this when an NEH shop e-mail (order confirmation, customer mail, admin copy) does not
arrive and postfix on the shop host already shows `status=sent (250 Great success)` to
`smtp.eu.mailgun.org`. From that point only Mailgun knows what happened.

Everything here is read-only. The one write at the bottom (removing a bounce suppression)
is allowed only when the user asks for it.

## Token

| | |
|---|---|
| File | `~/.tokens/mailgun` — the **raw key only**, no `VAR=` prefix, trailing newline ok |
| Load | `K=$(tr -d '[:space:]' < ~/.tokens/mailgun)` |
| Use | `curl -s --user "api:$K" ...` (HTTP basic, user `api`) |
| Creation | user-only, account API key with the **Support** role, see `../token-creation.md` |

Never echo the key, never put it in a URL, never commit it.

## Regions and base URLs

NEH shop hosts relay to `[smtp.eu.mailgun.org]:2525`, so shop domains live in the **EU**
region. The same account API key is accepted by both regions, but a domain exists in only
one of them; querying the wrong region gives `404 Domain not found`.

| Region | Base URL |
|---|---|
| EU (all NEH shop domains, 100+ domains) | `https://api.eu.mailgun.net` |
| US (check here only if EU returns 404) | `https://api.mailgun.net` |

API timestamps are UTC. The shop host logs in local time (CEST = UTC+2 in summer), so a
postfix line at `16:55:35` is `14:55:35Z` in Mailgun.

## Which Mailgun domain did the mail go through?

Postfix picks the SMTP credential from the **envelope sender domain**
(`smtp_sender_dependent_authentication = yes`):

1. `/etc/postfix/sasl_passwd_autogenerated` — one line per shop sender domain, written by
   `mailgunSyncDomains.sh` (neh-infrastructure, `roles/neh-install/files/`). Keyed on the
   domain of `ShopData.service_email` ("E-post till kundtjänst"). Only domains Mailgun
   reports as `active` get a line.
2. `/etc/postfix/sasl_passwd` — platform domains (`@shop.nordiskehandel.com`,
   `@nordiskehandel.com`, `@rootmail*.nordiskehandel.com`, …).
3. Fallback `[smtp.eu.mailgun.org]:2525` — used when the sender domain matches nothing.
   The mail then goes out through whatever Mailgun domain that credential belongs to, with
   that domain's DKIM, so DMARC fails for the real sender domain.

```sh
sudo sed 's/:[^:]*$/:.../' /etc/postfix/sasl_passwd_autogenerated   # passwords hidden
sudo journalctl --since "16:40" --no-pager | grep 'postfix/'          # queue id, from, to, 250
```

The postfix `cleanup` line gives the Message-ID (`<queue-id@host>`); search Mailgun for it.

## Query recipes (verified)

```sh
K=$(tr -d '[:space:]' < ~/.tokens/mailgun); B=https://api.eu.mailgun.net; D=example.com

# list domains in the account (paged, limit max 1000)
curl -s --user "api:$K" "$B/v4/domains?limit=100" \
  | jq -r '.total_count as $t | "total=\($t)", (.items[] | [.name, .state, .type] | @tsv)'

# one domain: state must be "active" for mailgunSyncDomains.sh to hand it to postfix
curl -s --user "api:$K" "$B/v3/domains/$D" | jq '.domain | {state, smtp_login, is_disabled, created_at}'

# delivery events, newest first (accepted / delivered / failed / rejected / complained)
curl -s --user "api:$K" "$B/v3/$D/events?limit=25" \
  | jq -r '.items[] | [(.timestamp|todate), .event, .recipient,
      (.message.headers["message-id"] // ""),
      (.["delivery-status"].code // "" | tostring),
      (.["delivery-status"].description // .["delivery-status"].message // .reason // "" | .[0:160])] | @tsv'

# filter by recipient, event type, or time window (RFC 2822 or unix seconds; begin/end)
curl -s --user "api:$K" "$B/v3/$D/events?limit=25&recipient=someone%40example.net"
curl -s --user "api:$K" "$B/v3/$D/events?limit=25&event=failed"
curl -s --user "api:$K" "$B/v3/$D/events?limit=25&begin=1760277600&end=1760281200&ascending=yes"

# suppression lists for the domain
curl -s --user "api:$K" "$B/v3/$D/bounces"      | jq -c '.items[] | {address, code, error, created_at}'
curl -s --user "api:$K" "$B/v3/$D/complaints"   | jq -c '.items[]'
curl -s --user "api:$K" "$B/v3/$D/unsubscribes" | jq -c '.items[]'
```

Events are kept for a limited time (days, plan dependent), so query soon after the send.
A `failed` event carries the remote server's reply in `delivery-status.message`; a Google
`550 5.1.1 … does not exist` means the recipient mailbox is wrong, not the sender.

## Reading the result

| Mailgun shows | Meaning | Where to look next |
|---|---|---|
| no event for the Message-ID on domain D | postfix used another credential | the sasl maps above, then the fallback credential's domain |
| `accepted` then `delivered` | Mailgun is done | recipient spam folder / Google Workspace quarantine (same-domain sender and recipient is often filtered) |
| `accepted` then `failed`, code 550 | remote server rejected | the message text: no such user, DMARC or spam policy, blocklist |
| `failed` with "Not delivering to previously bounced address" | recipient is on the domain's bounce list | remove it (below) or use another address |
| `rejected` | Mailgun refused before sending | domain not active, sandbox, or recipient not authorised |
| domain `state` ≠ `active` | DKIM/SPF not verified | shop DNS: `starweb._domainkey.<domain>` CNAME → `dkim.nordicshops.com`, SPF `include:spf-for-shops.nordicshops.com`, then rerun `mailgunSyncDomains.sh` on the host |

## The one allowed write

A hard bounce puts the address on the domain's bounce list and every later send to it is
suppressed. Remove it only when the user asks:

```sh
curl -s --user "api:$K" -X DELETE "$B/v3/$D/bounces/someone%40example.net"
```

Never create, verify or delete domains or keys from here; that is `mailgunSyncDomains.sh`
(domains) or the user (keys).
